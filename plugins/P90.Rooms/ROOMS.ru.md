# P90 Rooms 0.2.0 — собственные комнаты

Плагин `p90.rooms` для P90 Nexus. Устанавливается на компьютер хоста. Для входа игрок использует обычную кнопку взаимодействия с созданной плагином закрытой дверью. Просто пройти мимо недостаточно. Второе взаимодействие с дверью внутри комнаты возвращает к входу.

## Что получилось

Каждая комната получает собственную пару дверей. Вход хранится относительно выбранной комнаты карты: при изменении её положения и поворота вход перемещается вместе с ней. Интерьер находится отдельно от процедурной карты. Можно создать много независимых комнат; специального ограничения количества нет, но память, производительность и допустимые координаты конечны.

Плагин создаёт **свои экземпляры** штатной Locked Door. Он не превращает все закрытые двери карты в телепорты. Каждая дверь связана только со своей комнатой.

На трёх разных генерациях карты проверены привязки двух комнат. На локальном хосте также проверены вход через игровой обработчик взаимодействия, выход, задержка повторного перехода, сохранение строительных объектов, перезагрузка без дубликатов, остановка и повторный запуск плагина. Федор подтвердил практическую работу плагина и у других игроков.

**Граница гарантии:** на любом сиде, где есть ровно одно выбранное основание, используется его положение и поворот. Если нужная комната отсутствует или найдены два одинаковых основания, плагин отказывается создавать этот вход и пишет причину в `rooms.list`. Он не выбирает случайную комнату. Для входа, который должен появляться каждый раунд, выбирай комнату, обязательную для используемого режима карты. Одинаковое название не позволяет автоматически приспособить вход к изменившейся геометрии после обновления игры.

## Установка

Нужен уже установленный P90 Nexus с поддержкой описаний команд и поддерживаемая сборка SCP Project 90. Сам плагин не заменяет Nexus. В комплекте Nexus есть отдельная инструкция установки на чистую игру.

1. Закрой игру.
2. Из нового комплекта `release/plugins` скопируй **папку P90.Rooms целиком** в **P90 → plugins** внутри нужной игры. Получится `P90/plugins/P90.Rooms/P90.Rooms.dll`. Для этого способа нужен Nexus 0.3.0 или новее. Прежний отдельный комплект `P90 Rooms` с ручным копированием DLL также поддерживается.
3. Запусти игру, создай свой сервер и дождись появления персонажа.
4. Открой `P90 Console.cmd`, введи `pl`. В списке должен быть `p90.rooms` в рабочем состоянии.
5. Введи `com`: консоль покажет команды с владельцем `p90.rooms`, описанием и примером использования.

Вместо ручного копирования можно открыть PowerShell в папке комплекта и выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1 -GamePath "D:\steam\steamapps\common\SCP Project 90"
```

Путь замени на папку своей игры. Установщик сохраняет резервную копию прежней DLL, проверяет контрольную сумму и не меняет настройки комнат. Примеры JSON устанавливать не нужно. При первом запуске создаются общие настройки `P90/config/p90.rooms.json` и папка `P90/config/rooms` для отдельных комнат. При обновлении старый общий конфиг автоматически копируется в `.bak`, а его комнаты переносятся в отдельные файлы; геометрия старых комнат сохраняется.

Для обновления DLL закрой и снова запусти игру. Команда `res` перечитывает настройки и перезапускает уже загруженный код, но не заменяет DLL в памяти.

## Первая комната: по шагам

Все следующие команды вводятся в **консоли Nexus**, без PowerShell-обёрток.

1. Введи `players`. Найди себя и запомни **ConnectionId**. В примерах используется `0`; если у тебя другое число, подставляй его. Команду `players` предоставляет `sample.server`, он должен работать.
2. Приди в комнату карты, где нужен вход. Введи `rooms.anchors 0`, заменив `0` своим ConnectionId из первого шага. Команда покажет **только комнату этого игрока** и готовую строку `rooms.create` с её названием и твоим ID. Название новой комнаты `my-room` в этой строке можешь заменить на своё.
3. Встань на свободный пол и поверни персонажа туда, где будет дверь. Она появится примерно **в двух метрах перед персонажем**. Оставь место до стены. Текущее положение персонажа станет точкой возврата. Комната определяется по полу под ногами, а не по ближайшему центру. Если определить её нельзя, отойди от дверного проёма внутрь комнаты и повтори команду.
4. Создай заготовку:

```text
rooms.create my-room "LCZ Office 1" 0
```

5. Включи её:

```text
rooms.enable my-room
```

6. Подожди несколько секунд и введи `rooms.list`. `Ready` содержит готовые комнаты, `Problems` — причины отказа. Появится дверь; используй её обычной игровой кнопкой взаимодействия.

Внутри будет заготовка **16×12 метров, высотой 4 метра**: пол, стены, потолок и свет. Закрытая дверь внутри ведёт обратно. Между переходами есть задержка 1,5 секунды. Размер и форма задаются в собственном файле комнаты; ниже есть готовый пример L-образного плана.

Если дверь стоит плохо, вернись в нужную комнату карты, выбери новое место и направление, затем введи:

```text
rooms.entry my-room 0
```

Если `Problems` сообщает, что точка занята или под ней нет пола, выбери свободный участок и повтори эту команду. Плагин проверяет точки появления игрока; свободное место для самой двери нужно выбирать самому.

Для второй комнаты повтори создание с другим ID, например `my-room-2`. Можно привязать несколько входов к одной комнате карты. Они останутся независимыми. ID начинается с маленькой латинской буквы; дальше допустимы маленькие латинские буквы, цифры, точка и дефис, всего до 64 символов.

## Строительство и сохранение

```text
rooms.goto my-room 0
```

Это переносит выбранного игрока внутрь готовой комнаты. Строй и меняй объекты штатным игровым инструментом создания объектов. Когда результат устроит:

```text
rooms.save my-room
```

Команда сохраняет тип, положение, поворот, размер и индекс материала строительных объектов `SpawnTool` в области комнаты. Она также сохраняет оставшиеся части исходного короба. Двери-порталы исключаются: их положение задаётся отдельно. Произвольные игровые сущности, предметы, игроки, дополнительные свойства света, состояния дверей и другие специальные параметры не сохраняются этой версией.

У новых комнат область сохранения простирается на 50 метров в обе стороны по X и Z и на 30 метров вверх и вниз от центра интерьера. У старых комнат сохраняется прежний `CaptureHalfSize`. Увеличь его, если строишь за пределами области. Учитывается положение центра объекта, а не вся его видимая поверхность. Область поворачивается вместе с интерьером.

**`rooms.save` переводит комнату из секций в отдельные объекты:** сохраняет построенную геометрию в `Objects`, а `Layout` делает `null`. Так ручные изменения не теряются при следующей генерации. После этого размеры меняются через `Objects` или игровой строительный инструмент. Чтобы снова строить по секциям, задай `Layout` и очисти `Objects`, предварительно сохранив копию файла.

После сохранения добавленные объекты принадлежат плагину: при перестройке он удаляет их и создаёт заново по конфигу. **Сохраняй изменения до перезагрузки, выключения комнаты, остановки плагина или завершения игры.** Несохранённые посторонние объекты не становятся управляемыми автоматически и могут остаться отдельно до завершения сцены.

Чтобы проверить сохранение, введи `rooms.reload`, подожди несколько секунд и снова зайди. Для возврата через консоль:

```text
rooms.back 0
```

## Все команды

В примерах `my-room` — ID комнаты, `0` — ConnectionId игрока.

| Команда | Что делает |
|---|---|
| `rooms.list` | Показывает настройки, готовые комнаты и причины отказа. |
| `rooms.file my-room` | Показывает полный путь к файлу этой комнаты. |
| `rooms.layout my-room box` | Заменяет геометрию прямоугольной заготовкой 16×12 м. Предыдущий файл сохраняется в `.bak`, вход на карте остаётся. |
| `rooms.layout my-room l` | Заменяет геометрию L-образной заготовкой 256 м². Предыдущий файл сохраняется в `.bak`, вход на карте остаётся. |
| `rooms.anchors 0` | Показывает комнату указанного игрока и готовую команду создания входа. ID берётся из `players`. |
| `rooms.objects` | Показывает доступные имена Prefab и номера материалов. |
| `rooms.where 0 "LCZ Office 1"` | Показывает положение игрока в мире и относительно выбранного основания. |
| `rooms.where 0` | Выбирает ближайшее основание; это не обязательно фактическая комната игрока, проверь название. |
| `rooms.create my-room "LCZ Office 1" 0` | Создаёт выключенную заготовку, запоминает вход и возврат. |
| `rooms.entry my-room 0` | Перезаписывает вход и возврат по текущему положению игрока. |
| `rooms.enable my-room` | Включает комнату. |
| `rooms.disable my-room` | Выключает комнату. |
| `rooms.reload` | Перечитывает общий JSON и отдельные файлы комнат, перестраивает комнаты. Ошибочный JSON не заменяет действующие настройки. |
| `rooms.goto my-room 0` | Переносит игрока внутрь готовой комнаты. |
| `rooms.back 0` | Возвращает игрока к входу комнаты, в которую его отправил плагин. |
| `rooms.save my-room` | Сохраняет строительные объекты в области интерьера. |
| `sp p90.rooms` | Останавливает весь плагин, удаляет его объекты и команды. |
| `st p90.rooms` | Снова запускает остановленный плагин. |
| `res p90.rooms` | Перезапускает плагин с чтением конфига. |
| `com` | Получает актуальные команды, их описания и принадлежность плагинам. |

`entry`, `enable`, `disable`, `layout` и `reload` перестраивают **все включённые комнаты**. При очистке плагин пытается вернуть отслеживаемых посетителей к соответствующим входам. Возврат при очистке не ждёт освобождения точки, поэтому заранее попроси игроков выйти, если меняешь комнату во время игры. `rooms.back` не является общей командой возврата после любого телепорта: она работает для персонажа с зарегистрированным посещением.

Для удаления комнаты сначала выключи её, перенеси её JSON из папки `rooms` в резервную папку и выполни `rooms.reload`.

## Подробно о конфиге

Для изменения комнаты введи **`rooms.file my-room`**, скопируй выданный путь и открой этот файл Блокнотом. Например, в рабочей копии это **`D:\scp project90\P90\config\rooms\my-room.json`**. В Steam-копии — **`D:\steam\steamapps\common\SCP Project 90\P90\config\rooms\my-room.json`**.

Общие настройки находятся в **P90 → config → p90.rooms.json**. Редактируй файлы той игры, которая запущена. Перед ручными изменениями сохрани копию файла вне папки `rooms`. После изменений сохрани JSON и выполни `rooms.reload`. Пока редактируешь, не выполняй команды, которые сохраняют конфиг: они могут перезаписать ещё не загруженные изменения. В папке `rooms` каждый файл `.json` считается комнатой; имя файла должно совпадать с её `Id`.

### Размер и L-образная форма

Самый простой способ заменить старый маленький короб: `rooms.layout my-room l` для L-образной формы или `rooms.layout my-room box` для прямоугольной. Команда заменяет всю геометрию и точки появления/выхода внутри, оставляет привязку входа на карте и делает резервную копию сохранённого файла. Если есть несохранённые ручные постройки, сначала выполни `rooms.save my-room`. Для восстановления останови плагин, скопируй нужный `.bak` поверх JSON этой комнаты и снова запусти плагин.

В файле новой комнаты найди `Layout`. Это план из прямоугольных секций. Одна секция с `Width: 16` и `Depth: 12` даёт комнату 16×12 метров. `Height` — общая высота. `X` и `Z` — положение центра секции относительно центра интерьера; все размеры в метрах.

Чтобы получить L-образную комнату, замени значение `Layout` следующим объектом и установи `Objects` в `[]`:

```json
"Layout": {
  "Height": 4,
  "WallThickness": 0.3,
  "FloorThickness": 1,
  "FloorMaterial": 10,
  "WallMaterial": 12,
  "CeilingMaterial": 12,
  "Ceiling": true,
  "Lights": true,
  "Sections": [
    { "X": 0, "Z": 0, "Width": 16, "Depth": 12 },
    { "X": 4, "Z": 10, "Width": 8, "Depth": 8 }
  ]
},
"Objects": []
```

Это фрагмент файла, не весь конфиг. Сохрани остальные поля, особенно `AnchorRoom`, `Entrance`, `Return` и `Interior`. Первая секция идёт от X=-8 до X=8 и от Z=-6 до Z=6. Вторая продолжает её с одной стороны: от X=0 до X=8 и от Z=6 до Z=14. В стыке стенки не будет. Общая площадь — 256 м². Можно добавлять секции для Т- и П-образных планов; пересечения объединяются без двойных полов. Не оставляй между секциями зазор, если нужен проход. Раздельные секции допускаются, но сами собой не соединяются.

Для прямоугольной комнаты большего размера достаточно поменять `Width` и `Depth` первой секции. При уменьшении комнаты или изменении формы проверь, что `Arrival` и `Exit` остаются над её полом. Их X/Z задаются относительно центра интерьера. Новая заготовка использует Arrival `[0, 0, -2]` и Exit `[0, 0, -5.7]`.

Допускается до 32 секций в одном плане; это ограничение сложности генератора, а не количества комнат. Размер секции — от 3 до 100 м, центр — в пределах ±150 м, высота — 3.5–30 м. Толщина стен — 0.1–2 м, пола — 0.3–5 м. `Objects` можно использовать одновременно с `Layout` для дополнительных перегородок, колонн и деталей. Для многоуровневых и произвольных форм используй `Objects`; секции имеют общий горизонтальный пол и высоту. Поворот всего интерьера задаётся отдельно.

В комплекте есть `Examples/l-room.json` — целый пример выключенной комнаты. Его привязку нужно настроить для своей карты; удобнее создать комнату командой и перенести в её файл только `Layout` и пустой `Objects`.

JSON требует двойных кавычек, десятичной точки и запятых между элементами; после последнего элемента запятая не ставится. Комментарии в JSON не добавляй.

### Общие поля

| Поле | Значение и смысл |
|---|---|
| `SchemaVersion` | `1`; версия формата. |
| `Enabled` | `true` включает работу комнат, `false` выключает все комнаты. |
| `GenerationSettleSeconds` | `4`; ожидание стабильной карты, от 2 до 60 секунд. |
| `InteractionDistance` | `4`; максимальное расстояние от персонажа до основания двери при взаимодействии, от 1 до 6 метров. Не увеличивает дальность игрового наведения. |
| `CooldownSeconds` | `1.5`; задержка между переходами через двери одного персонажа, от 0.5 до 60 секунд. Явные команды `goto`/`back` задержку обходят. |
| `CheckDestination` | `true`; проверять свободное место для тела персонажа. Пол ищется всегда, в пределах 4 метров под точкой. Рекомендуется оставить включённым. |
| `SeparateRoomFiles` | `true`; комнаты читаются из отдельных JSON в папке `rooms`. Не меняй вручную на `false`. |
| `Rooms` | После автоматического переноса должен быть пустым `[]`; комнаты теперь находятся в отдельных файлах. |

### Поля одной комнаты

| Поле | Что означает |
|---|---|
| `Id` | Уникальное имя для команд. |
| `Enabled` | Включена ли конкретная комната. |
| `AnchorRoom` | Точное название комнаты, которое показывает `rooms.anchors ID`. |
| `AnchorRoot` | Точное имя основания `Root`. `create` заполняет автоматически. Пустая строка допускает любое основание с нужным `AnchorRoom`, но совпадение всё равно должно быть единственным. |
| `Entrance` | Положение и поворот входной двери **относительно основания карты**. |
| `Return` | Положение и поворот персонажа при выходе **относительно того же основания**. |
| `Interior` | Положение и поворот центра отдельного интерьера **в мировых координатах**. |
| `Arrival` | Точка поиска пола для появления персонажа **относительно Interior**. Высота тела над полом рассчитывается автоматически. |
| `Exit` | Положение и поворот выходной двери **относительно Interior**. |
| `CaptureHalfSize` | Половина размера области сохранения по каждой оси; каждое число от 1 до 200. |
| `Objects` | Список строительных объектов интерьера. |
| `Layout` | План из секций или `null` для полностью ручной геометрии в `Objects`. |

Каждое положение задаётся `Position: [X, Y, Z]`, каждый поворот — `Rotation: [X, Y, Z]` в градусах. Y направлена вверх. Локальные X и Z поворачиваются вместе с основанием: именно это сохраняет положение входа на другом сиде. Низ дверей автоматически выравнивается по полу с учётом формы штатной модели. При переходе плагин учитывает высоту и смещение игрового CharacterController; координата персонажа не равна координате его ступней.

У каждого объекта в `Objects` есть:

| Поле | Что означает |
|---|---|
| `Prefab` | Точное имя штатного шаблона из `rooms.objects`, например `Cube_ST`. |
| `Position` | Положение относительно Interior. |
| `Rotation` | Поворот относительно Interior. |
| `Scale` | Масштаб по трём осям; от 0.01 до 1000. Для исходного метрового куба соответствует размеру в метрах. |
| `Material` | Номер материала из `rooms.objects`; `-1` сохраняет материал шаблона. |

Пример одного объекта пола:

```json
{
  "Prefab": "Cube_ST",
  "Position": [0, -0.25, 0],
  "Rotation": [0, 0, 0],
  "Scale": [8, 0.5, 8],
  "Material": 10
}
```

`create` выбирает для интерьера свободную по X позицию, начиная с `[20000, 500, 20000]`, с шагом 100 метров. Для больших комнат самостоятельно увеличивай расстояние: автоматической проверки пересечения интерьеров нет. Все компоненты координат ограничены диапазоном ±100000. Это практическое ограничение, поэтому бесконечное число комнат в буквальном смысле невозможно.

## Если что-то не работает

* Нет `p90.rooms` в `pl`: проверь расположение DLL и перезапусти игру. Если плагин отображается с ошибкой, посмотри `P90/logs/p90.rooms.jsonl` и журналы ядра.
* Комната не появилась: `rooms.list` → `Problems`. Проверь включение комнаты, имя основания и свободный пол в точках `Return` и `Arrival`.
* Вход не появляется только на некоторых сидах: посмотри причину в `rooms.list`. Название комнаты, в которой стоишь, можно узнать через `rooms.anchors ID`. Используй обязательную комнату карты.
* Дверь не переносит: подойди ближе, наведи на неё и взаимодействуй. Подожди задержку. Если в точке появления стоит другой игрок, дождись освобождения. Причина отказа записывается в журнал плагина.
* После редактирования ничего не меняется: проверь папку запущенной игры и выполни `rooms.reload`.
* Ошибка неподдерживаемой сборки: плагин проверяет исходные файлы игры. Для новой сборки потребуется повторное исследование и адаптация. Не отключай проверку ради запуска неизвестных игровых методов.

## Проверка с другом — следующий шаг

Нужен игрок с обычной игрой **без Nexus и без этого плагина**. На своём сервере создай две комнаты и проверь:

1. Друг видит обе двери, пол, стены и добавленные объекты; размеры и материалы совпадают с тем, что видит хост.
2. Просто проходя мимо двери, он остаётся на месте.
3. При взаимодействии переносится именно нажавший игрок, а не хост или соседний игрок.
4. Выход возвращает к правильному входу; две комнаты не перепутаны.
5. После переподключения игрок видит уже созданные объекты.
6. После нового раунда с другим сидом входы остаются в выбранной комнате карты.

Сообщи результат и шаг, если возникнет проблема. Проверки на локальном хосте не заменяют этот сетевой тест.

## Для изменения плагина

Исходники проекта: `src/P90.Rooms/Settings.cs`, `RoomLayout.cs`, `RoomFiles.cs`, `RoomsPlugin.cs`, `P90.Rooms.csproj`; в отдельном комплекте их копии находятся в `Sources/src`. Сборка из корня проекта: `dotnet build src/P90.Rooms/P90.Rooms.csproj -c Release --configfile src/NuGet.Config`. Требуются .NET SDK, API Nexus, сгенерированные interop-сборки этой игры и её установленный загрузчик. Эти игровые сборки не входят в отдельный комплект плагина.

`Settings.cs` определяет формат конфигурации и валидацию. `RoomsPlugin.cs` отвечает за команды, поиск оснований, создание/удаление объектов, сохранение геометрии и обработку дверей. Проверка сборки подключается из `src/P90.GameAdapter/BuildGuard.cs`. Эта специализированная реализация использует внутренние методы конкретной версии игры; стабильный общий API ядра сам по себе не гарантирует её совместимости с обновлением игры.

Цепочка входа: штатный `PlayerInteract` отправляет команду серверу → `Door.bqx(GameObject)` → плагин проверяет принадлежность двери, игрока, дистанцию, задержку и точку назначения → штатный `PlayerTransformSync.ckx` передаёт положение через игровой RPC. Двери и геометрия создаются через штатные сетевые префабы. Новых компонентов для клиента не требуется по устройству реализации; видимость, синхронизацию и позднее подключение нужно подтвердить отдельным клиентом.

Локальные материалы исследования и проверки находятся в `research/rooms`. Диагностический плагин `P90.RoomProbe` не нужен для обычной игры и в установочный комплект не включён.
