# P90 SDK — создание плагина

Этот комплект содержит публичную библиотеку API major 1, шаблон и генератор проекта. Библиотеки Unity, Mirror, BepInEx и Assembly-CSharp автору обычного плагина не нужны. Использование уже собранных плагинов описано в [руководстве хоста](docs/PLUGINS.ru.md).

В `examples/OnechikHello` сохранён собранный и проверенный самостоятельный проект. Его проверенная DLL находится в `verified-example/OnechikHello.dll`; установка примера необязательна. SDK не меняет открытую игру.

## Подготовка и первый проект

Зафиксированный инструмент сборки — .NET SDK **10.0.401**, целевая платформа плагина — **net6.0**, runtime внутри проверенного загрузчика — **6.0.7**. SDK 10.0.401 уже установлен на компьютере Федора. Версия закреплена в global.json без автоматического перехода на другую. При первой сборке на другом компьютере NuGet может скачать reference packs .NET 6.0.36; NuGet.Config содержит только nuget.org. Сторонних PackageReference у примера нет. Версию и SHA256 API смотри в sdk-manifest.json.

В PowerShell из корня рабочей копии:

```powershell
Set-Location -LiteralPath 'D:\scp project90'
.\sdk\New-Plugin.ps1 -Name OnechikHello -Id onechik.hello -Destination 'D:\scp project90\MyPlugins\OnechikHello'
& '.\MyPlugins\OnechikHello\Build.ps1'
```

Назначение должно быть новым каталогом: генератор не перезаписывает существующие проекты. Name — имя сборки/пространства имён из латинских букв и цифр, начиная с заглавной буквы. Id — уникальное строчное имя, например `onechik.hello`. Генератор ограничивает ID 47 символами, чтобы осталось место для суффиксов команд. Зарезервированные имена файлов Windows и префикс p90. не подходят.

Содержимое нового проекта полностью самостоятельно:

```text
Plugin.cs             исходник плагина
Plugin.csproj         ссылка только на lib/P90.API.dll
lib/P90.API.dll        публичный контракт
global.json           версия инструмента сборки
NuGet.Config          источник reference packs
Build.ps1             восстановление и Release-сборка
```

Проект можно перенести в другую папку вместе с этими файлами: ссылок на исходники ядра или папку игры в нём нет. При успехе DLL появится в `bin\Release\net6.0\OnechikHello.dll`. API не копируется в выходной каталог благодаря Private=false.

## Установка и проверка

1. Закрой игру штатно.
2. Создай папку `OnechikHello`, положи в неё **OnechikHello.dll** и скопируй эту папку в `D:\scp project90\P90\plugins`. Для передачи пользователям отдавай эту папку целиком. Не устанавливай вторую копию P90.API.dll: её уже предоставляет ядро.
3. Запусти игру, дождись меню и проверь:

```powershell
.\scripts\P90.ps1 p90.plugins | Format-List
.\scripts\P90.ps1 onechik.hello.hello | Format-List
.\scripts\P90.ps1 onechik.hello.status | Format-List
```

Приветствие должно быть `Hello, Onechik!`. В меню Server=False — нормальный результат. Для объявления создай свой хост обычным способом, дождись персонажа и выполни:

```powershell
.\scripts\P90.ps1 -Command onechik.hello.announce -Arguments 'Привет от нового плагина!' | Format-List
```

Федор подтвердил практическую работу комплекта у других людей; подробности отдельных сетевых сценариев не перечислены. Публичный API не обещает успешной отправки в меню или при подключении к чужому хосту.

## Как устроен пример

Атрибут Plugin задаёт ID, отображаемое имя, числовую версию и major API. Класс реализует IP90Plugin. Start получает IPluginContext; Stop завершает поведение. У плагина должен быть публичный конструктор без аргументов. В нём не следует выполнять игровую работу: сервисы становятся доступны в Start.

Пример читает Settings из своего конфига, регистрирует три команды и подписывается на два события. Ничего автоматически в игру не отправляет. Счётчик observed означает число наблюдений доступности персонажей после Start, включая снимок при старте; он не является текущим числом игроков. При ServerStopped сбрасывается. Точный текущий список находится в Snapshot.Players.

Start может вызываться много раз на одном объекте плагина. Сбрасывай временные поля в Start. При Stop ядро освобождает регистрации, созданные через контекст; самостоятельно созданные ресурсы освобождает сам плагин. После Stop контекст и сохранённый через него Server больше нельзя использовать. Исключение Start вызывает попытку Stop и откат регистраций; исключение Stop не отменяет очистку.

Каждый Register/Subscribe возвращает IDisposable. Его можно вызвать досрочно; повторный Dispose допустим. Если сохранить токен не нужно, ядро само освободит активную регистрацию при остановке. Изменять Unity/API или освобождать токены из Task.Run и других потоков нельзя: эти операции принадлежат потоку ядра.

## Краткий справочник API

| Сервис/тип | Назначение |
|---|---|
| context.PluginId | ID текущего плагина |
| context.Log.Info/Error | Запись в собственный JSONL-журнал |
| context.Config.Load<T>() | Прочитать конфиг; создать стандартный, если файла нет |
| context.Config.Save(value) | Сохранить конфиг через временный файл и замену |
| context.Commands.Register(name, handler) | Зарегистрировать локальную команду |
| CommandContext.Arguments | Отдельные аргументы, переданные оператором |
| CommandResult.Ok/Fail | Успех или отказ с объяснением |
| context.Events.Subscribe<T>(handler) | Подписка на тип события |
| context.Server.Snapshot | Состояние сервера и готовых персонажей без типов игры |
| context.Server.Broadcast(text) | Штатный RPC объявления, только на активном сервере |
| CorePulse | Диагностический импульс Update, не игровой таймер |
| ServerStarted / ServerStopped | Наблюдение активности серверной сессии |
| PlayerAvailable / PlayerUnavailable | Наблюдение готового сетевого персонажа |

ID плагинов и имена команд ядра: 3–64 символа, первая — строчная латинская буква, далее буквы, цифры, точки, дефисы. `core` зарезервирован как ID, `p90.` — как префикс команд. Не используй имена устройств Windows: con, aux, nul, prn, com0…com9, lpt0…lpt9, в том числе перед точкой. Рекомендуется начинать команды с ID плагина для исключения конфликтов.

События игроков не означают каждый транспортный connect/disconnect: они наблюдаются в Update по готовым identity. Респавн/смена сцены может заменить NetId. История событий новому подписчику не воспроизводится; начальное состояние бери из Snapshot. Полей SteamID, роли, урона и инвентаря в этом API пока нет.

Broadcast допускает до 512 символов, без `<`, `>` и управляющих символов кроме перевода строки. Пустой текст очищает поле. Успех означает передачу в штатную отправку, не подтверждение клиента; автоматического повтора, истории или времени показа нет. Нативные игровые объекты в плагине хранить не требуется.

## Настройки, ошибки и обновления

Конфиг примера: `P90\config\onechik.hello.json`, журнал: `P90\logs\onechik.hello.jsonl`. Измени Greeting, сохрани UTF-8 JSON и выполни `p90.restart` с аргументом `onechik.hello` через P90.ps1. Повреждённый JSON не заменяется стандартным: исправь файл и запусти плагин снова.

Ошибки обычного обработчика фиксируются в журнале, остальные обработчики продолжаются. Это не защита от бесконечного цикла, нативного падения или произвольного кода DLL. Все плагины разделяют процесс и AssemblyLoadContext. Автоматического разрешения конфликтующих сторонних зависимостей и полноценной выгрузки сборок нет.

Для изменения исходного кода: закрой игру, запусти Build.ps1, замени DLL и запусти игру. `p90.restart` перечитывает конфиг и запускает тот же экземпляр; новую DLL в текущий процесс не загружает. Пакет SDK не является установщиком ядра или полной поставкой игры.

## Проверки этого комплекта

В этапе 6 отдельный OnechikHello создан генератором и собран без ссылок на Core/Unity/Mirror. Его бинарник проверяется P90.SdkVerifier на копии комплектного runtime 6.0.7: команды, запрет отправки без сервера, события, сброс состояния и 100 перезапусков. Само ядро проходит 15 групп проверок, включая 10 000 досрочных освобождений регистраций и 1000 модельных серверных сессий. Это локальные проверки; модельная сессия не заменяет настоящий сетевой тест.

Полная документация выпуска: [оглавление](docs/README.ru.md), [API](docs/API.ru.md), [разработка ядра](docs/CORE-DEVELOPMENT.ru.md). В поставке P90 Nexus из папки комплекта генератор вызывается как .\SDK\New-Plugin.ps1; пути выше показаны для исходного рабочего проекта.
