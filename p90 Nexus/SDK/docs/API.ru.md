# Справочник P90 API major 1

Источник истины — `P90.API/Contracts.cs` и `P90.API/Game.cs` в исходниках. Пространство имён всех перечисленных типов: `P90.API`. Плагин ссылается на одну `P90.API.dll` из SDK с `Private=false`; установленное ядро предоставляет библиотеку во время выполнения.

## Метаданные и экземпляр

```csharp
[Plugin("author.example", "Example", "1.0.0", apiMajor: 1)]
public sealed class ExamplePlugin : IP90Plugin
{
    public void Start(IPluginContext context) { }
    public void Stop() { }
}
```

`PluginAttribute(string id, string name, string version, int apiMajor = 1)` имеет свойства `Id`, `Name`, `Version`, `ApiMajor`. Атрибут не наследуется. Версия должна распознаваться `System.Version.TryParse`: используй `1.0.0`, а не `1.0.0-beta`. Имя не может состоять только из пробелов. Класс должен быть конкретным, без открытых generic-параметров, реализовать `IP90Plugin` и иметь публичный конструктор без аргументов. Метаданные проверяются до создания объекта.

ID: 3–64 символа, первая строчная латинская буква, остальные `[a-z0-9.-]`. Запрещены `core` и имена устройств Windows `con`, `prn`, `aux`, `nul`, `com0`…`com9`, `lpt0`…`lpt9`, в том числе перед точкой. Сопоставление зарегистрированных ID не зависит от регистра, но метаданные принимаются только в нижнем регистре. Генератор SDK строже: 3–47 символов и запрет префикса `p90.`, чтобы команды с суффиксами поместились в лимит.

`Start` вызывается повторно на **том же экземпляре** при перезапуске. На каждый Start выдаётся новый контекст. Временные поля сбрасывай самостоятельно. Если Start выбросил исключение, ядро пытается вызвать Stop, снимает регистрации и ставит `Faulted`. При обычном Stop контекст ещё доступен в методе Stop; после возврата или исключения регистрации снимаются, контекст становится недействительным, состояние — `Stopped`. Исключение обработчика команды/события само по себе не переводит плагин в Faulted.

## IPluginContext и потоки

| Свойство | Тип | Назначение |
| --- | --- | --- |
| `PluginId` | `string` | ID владельца |
| `Log` | `IPluginLog` | Журнал |
| `Config` | `IPluginConfig` | Один JSON-конфиг владельца |
| `Events` | `IPluginEvents` | Подписки на события |
| `Commands` | `IPluginCommands` | Локальные команды |
| `Server` | `IGameServer` | Снимок и объявление |

Вызовы сервисов, обработчики и освобождение токенов выполняются на потоке ядра (в игре — основной поток Unity). Из `Task.Run`, таймера или фонового потока вызывать их нельзя. После Stop нельзя использовать сохранённые сервисы старого контекста, даже если плагин уже запущен заново: получишь `ObjectDisposedException`. Потоковая ошибка даёт `InvalidOperationException`.

Для вычислений в фоне передай туда собственные данные без объектов Unity; результат забирай на основном потоке через собственную потокобезопасную очередь в обработчике CorePulse. Сам API очереди задач, async-команд и планировщика не предоставляет. Не используй `async void` в обработчиках: исключение после await выходит за пределы обычного перехвата ядра. Не блокируй главный поток ожиданием фоновой задачи.

## Журнал и конфигурация

`IPluginLog.Info(string message)` и `Error(string message)` добавляют запись в `P90/logs/<id>.jsonl` и передают её загрузчику. Поля записи: `Utc`, `PluginId`, `Level`, `Message`. Ротация и ограничение размера не реализованы; лог на каждый кадр быстро разрастётся.

`IPluginConfig.Load<T>() where T : class, new()` читает `P90/config/<id>.json`. При отсутствии файла создаёт `new T()` и сохраняет. Имена свойств при чтении нечувствительны к регистру. При повреждённом JSON или корневом `null` выбрасывает ошибку; файл не заменяется значениями по умолчанию. Поля класса по умолчанию не сериализуются — используй публичные свойства `get; set;`.

`Save<T>(T value) where T : class` сериализует объект с отступами во временный файл и заменяет целевой. `null` запрещён. Проверки диапазонов и миграции схемы — задача плагина. Не сохраняй при каждом импульсе. Прочитанный объект не связан с файлом автоматически: изменения вступают в силу после Save или повторного Load, в зависимости от логики плагина.

## Команды

С 1 октября 2026 можно задать описание и способ использования при регистрации:

```csharp
context.Commands.Register(
    "myplugin.hello",
    _ => CommandResult.Ok("Привет!"),
    description: "Показывает приветствие.",
    usage: "myplugin.hello");
```

`description` объясняет действие, `usage` — что вводить, включая аргументы или пример. ID владельца указывать не нужно: ядро берёт его из контекста, а не угадывает по префиксу команды. Описание ограничено 2048 символами (допускается LF), usage — 1024, управляющие символы запрещены. Пустые строки допустимы, null — нет. Эти тексты служат справкой и не проверяют аргументы автоматически.

Совместимость обеспечена дополнительным `IDescribedPluginCommands : IPluginCommands` и extension-методом `PluginCommandExtensions.Register(this IPluginCommands, string, Func<CommandContext, CommandResult>, string description, string usage)`. Старый IPluginCommands и его метод не изменены; ранее собранные плагины работают, их владелец известен, описание пустое. Для нового overload нужны обновлённые SDK/API и ядро с поддержкой описаний; API major остаётся 1. Новая библиотека API сама по себе без обновления ядра недостаточна. На реализации без этой возможности extension-метод выбрасывает NotSupportedException.

`CommandInfo(string Name, string PluginId, string Description, string Usage)` — запись каталога. `p90.commandinfo` возвращает JSON-массив этих записей для активных команд, включая старые регистрации. При Dispose/Stop запись удаляется. Старый p90.commands сохраняет список имён в текстовом формате. Консоль запрашивает новый каталог, группирует команды по PluginId и показывает описание и использование; при старом ядре доступен только прежний список имён.

```csharp
IDisposable Register(string name,
    Func<CommandContext, CommandResult> callback);
```

`CommandContext.Arguments` — `IReadOnlyList<string>`, копия переданных аргументов без имени команды. `CommandResult(bool Success, string Message)` — record; фабрики `Ok(message)` и `Fail(message)`. Возвращай Fail для ожидаемого отказа: неправильного ввода или неподходящего состояния игры. Исключения логируются и превращаются в отказ `Command handler failed; see plugin log.`; null-результат тоже считается отказом.

Правила имени команды совпадают с форматом ID; префикс `p90.` зарезервирован. Дубликат вызывает `InvalidOperationException`, некорректное имя — `ArgumentException`. Начинай имя с собственного ID, например `author.example.status`. Порядок обнаружения файлов не должен служить способом разрешения конфликтов.

Команды выполняются только оператором через локальный скрипт. В игре нет автоматически созданной команды чата, сетевой команды игрока или проверки его роли. Не принимай локальную модель доступа за готовую авторизацию для будущего удалённого интерфейса.

Register возвращает `IDisposable`: Dispose снимает конкретную регистрацию; повторный вызов допустим, но только на потоке ядра. Можно не сохранять токен, если регистрация должна жить до Stop: ядро её снимет. Досрочно освобождённые токены удаляются из учёта владельца.

## События

`IDisposable Subscribe<T>(Action<T> callback)` подписывает на **точный тип T**. История не воспроизводится, наследование типов автоматически не учитывается. Публичного `Publish` в контексте плагина нет; события публикует ядро. Получение исключения одним обработчиком не прерывает остальные; ошибки учитываются и записываются в лог. Обработчики запускаются синхронно, в порядке регистрации, только у активных плагинов.

| Тип record | Поля | Семантика |
| --- | --- | --- |
| `CorePulse` | `long Number` | Счётчик диагностических импульсов ядра |
| `ServerStarted` | `string SessionId` | Наблюдён переход сервера в активное состояние |
| `ServerStopped` | `string SessionId` | Наблюдён выход из активного состояния |
| `PlayerAvailable` | `string SessionId`, `PlayerSnapshot Player` | Наблюдён готовый персонаж |
| `PlayerUnavailable` | те же | Наблюдён выход/замена готового персонажа |

Загрузчик вызывает CorePulse приблизительно раз в секунду из Update; при задержках кадра пропущенные импульсы не догоняются. Это не точный таймер и не сигнал, что запущен сервер. Вызов `PluginHost.Tick()` из теста также создаёт импульс.

Адаптер опрашивает состояние в Update. События игроков не равны транспортным connect/disconnect. Игрок может уже подключиться, но ещё не иметь готовой identity. При смене NetId для того же ConnectionId сначала приходит Unavailable, затем Available. Изменение одного имени не создаёт эти события. Начальный список после Start бери из Snapshot.

При наблюдённом старте порядок: ServerStarted, затем Available. При остановке: Unavailable для старых персонажей, затем ServerStopped. Снимок обновлён до публикации этих событий; в обработчике остановки текущий Snapshot уже не содержит прежних игроков. Поле SessionId в самом событии позволяет обработать старую сессию. Смена сцены сама по себе не создаёт новую сессию, пока сервер остаётся активным. Полный stop/start между двумя опросами может быть не замечен.

## Снимки сервера и игроков

`IGameServer.Snapshot` возвращает `ServerSnapshot`:

| Поле | Тип | Как читать |
| --- | --- | --- |
| Supported | bool | Адаптер разрешён для этой сборки и не отключён из-за ошибки |
| IsServer | bool | Экземпляр выполняет серверную роль |
| IsClient | bool | Экземпляр выполняет клиентскую роль; у играющего хоста оба флага могут быть true |
| SessionId | string | Непостоянный ID наблюдаемой серверной сессии; вне сервера пустой |
| Scene | string | Имя наблюдаемой активной сцены |
| Players | IReadOnlyList&lt;PlayerSnapshot&gt; | Наблюдаемые готовые персонажи сервера |
| DisabledReason | string | Причина недоступности адаптера, иначе пустая строка |

`PlayerSnapshot(int ConnectionId, uint NetId, string Name)` содержит ID соединения, ID сетевого объекта и ник. Ни один ID не является SteamID или долговременной идентичностью пользователя. Храни данные с учётом SessionId и очищай на ServerStopped. Снимки не содержат Unity/IL2CPP-объектов. Сохранённый снимок не обновляется автоматически; для актуального состояния снова прочти Snapshot.

Список наблюдательный, а не обещание мгновенной синхронизации. Перед действием адаптер отдельно проверяет живое серверное состояние. В режиме чистого клиента серверного списка игроков нет. При Supported=false серверные операции недоступны, но общие локальные команды плагина могут продолжать работать.

## Broadcast

`CommandResult IGameServer.Broadcast(string text)` вызывает существующий RPC объявления. Условия: поддерживаемая сборка, активный сервер, хотя бы один готовый игрок и общий объект PlayerAdmin, наблюдаемый всеми готовыми игроками. Иначе возвращается Fail с причиной; во время загрузки карты можно повторить позже по осознанной команде.

Текст — до 512 единиц UTF-16 (`string.Length`), без `<`, `>` и управляющих символов, кроме `\n`. Пустая строка очищает объявление. `\r\n` нужно преобразовать в `\n`, поскольку `\r` не разрешён. Успех означает, что поставлен в отправку **один** игровой RPC, а не получено подтверждение клиента. Нет автоматического повтора, продолжительности, истории и доставки прошлых сообщений позднему игроку. После объявления очистку выполняет автор плагина или оператор.

Не вызывай Broadcast по одному разу для каждого игрока: каждая отправка уже распространяется на наблюдателей. Новые роли, предметы или сетевые сообщения не возникают от этого API; для них требуется отдельная работа в адаптере.
