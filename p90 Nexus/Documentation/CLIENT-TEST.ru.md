# Сценарий этапа 5: обычный клиент

Сценарии подготовлены на этапе 4 и сохранены для регрессии. 27 сентября Федор подтвердил работу сборки у себя и у других людей. Подробности отдельных сценариев A–E не перечислены; этот документ описывает процедуру, а не протокол их прохождения.

## Подготовка

- Компьютер хоста: наша рабочая копия `D:\scp project90`, Steam запущен. `p90.plugins` показывает sample.server в Active.
- Другой компьютер: отдельный Steam-аккаунт и обычная игра той же версии. Ему не нужны DLL P90, BepInEx, конфиги и скрипты.
- Запуски обычные, без selftest-флагов. Автотесты разработчика для этого сценария не запускаются: они используют локальный хост без публичного лобби.
- На хосте открой PowerShell и выполни `Set-Location -LiteralPath 'D:\scp project90'`.

## Проверки

### A. Подключение

Создай обычное Steam-лобби/хост через интерфейс игры. Для первого теста выбери Sandbox — на этой карте выполнена локальная проверка. Подключи второй компьютер штатным способом. После появления персонажей на хосте выполни:

```powershell
.\scripts\P90.ps1 server.status
.\scripts\P90.ps1 server.players
```

Ожидается Supported=true, IsServer=true и два игрока в Players. У клиента нет требования установить мод. Сохрани фактический результат, даже если подключение не удалось.

### B. Отображение и очистка

```powershell
.\scripts\P90.ps1 -Command server.announce -Arguments 'P90 TEST A — одно объявление для двух игроков'
```

Проверь текст и у хоста, и на втором компьютере. Нужен ответ именно о видимом тексте у удалённого игрока; Success=True на хосте его не заменяет. Затем:

```powershell
.\scripts\P90.ps1 -Command server.announce -Arguments 'P90 TEST B — замена первого текста'
.\scripts\P90.ps1 server.clear
```

Ожидается замена текста, затем очистка на обоих компьютерах. Сообщи, где расположен текст и нет ли повторов/ошибок. При сохранении старого текста после clear отметь это отдельно.

### C. Повторное и позднее подключение

Выйди вторым игроком, проверь список на хосте, подключись снова. Новый список должен снова содержать двух готовых игроков. Отправь новый уникальный текст `P90 TEST C` и проверь его у клиента.

История RPC не восстанавливается для позднего входа. Если объявление отправлено до подключения, отсутствие старого текста у вошедшего позже не считается ошибкой. Проверяется **новая** отправка после его готовности.

### D. Остановка и новый хост

Заверши хост через штатный интерфейс игры и вернись в главное меню. `server.status` должен показывать IsServer=false, пустые SessionId/Players. Попытка server.announce должна быть отклонена.

Создай хост снова, подключи клиента и повтори B. SessionId должен отличаться от первой сессии. Если тестируется карта с раундами, дополнительно проверь штатный переход к следующему раунду и новую отправку после загрузки обоих игроков. Повторные PlayerAvailable при создании новых игровых персонажей допустимы: событие относится к сетевому персонажу, не только к входу Steam-аккаунта.

### E. Плагин на компьютере, который стал только клиентом

На чистой копии второго компьютера создай обычный хост. С нашей модифицированной копии подключись к нему как клиент. В её локальном PowerShell выполни server.status и server.announce.

Ожидается IsServer=false и отказ объявления. Изменений у хоста или других игроков быть не должно. Плагины ядра при этом могут оставаться Active: ограничиваются игровые серверные действия.

## Что сообщить

Для пунктов A–E: «прошёл / не прошёл / не проверен», карта, число игроков, фактический результат. Для B отдельно: видит хост / видит клиент / заменяется / очищается. Для D: новая сессия / новый раунд. Для E: статус и текст отказа.

При ошибке приложи текст ответа команды и соответствующие `BepInEx\LogOutput.log`, `P90\logs\sample.server.jsonl`, журнал запуска `P90\logs\runs\...\core.jsonl`. Не перезапускай игру до сохранения общего журнала, если это возможно. На основе результата ассистент исправляет конкретную проблему и выдаёт повторный сценарий; заранее успешные результаты не записываются.
