# Сборка, проверки и выпуск

## Поддерживаемая конфигурация 0.2.0

Windows x64; игра с отпечатками из `supported-game.json`; Unity 2022.3.16f1 IL2CPP; BepInEx Unity IL2CPP 6.0.0-be.788 (5b766a3); UnityDoorstop 4.5.0; встроенный .NET runtime 6.0.7; API major 1. Версии зафиксированы как проверенный набор, а не как рекомендация автоматически обновлять компоненты. Список сторонних компонентов и лицензии — в THIRD-PARTY.md комплекта.

## Команды разработчика

Из корня подготовленной рабочей игры:

```powershell
.\scripts\Build-Core.ps1
.\scripts\Build-Sdk.ps1
.\scripts\Test-Sdk.ps1
```

Build-Core выполняет restore, Release build и Core.Tests через доступный системный runtime с roll-forward Major. Поэтому Test-Sdk отдельно запускает Core.Tests и независимый пример на **копии встроенного 6.0.7**. Скрипт берёт dotnet.exe/hostfxr из установленного SDK, runtime — из dotnet игры; системный runtime не заменяет.

После осознанной установки собранных DLL в отдельную рабочую копию (игра закрыта) доступны игровые проверки:

```powershell
.\scripts\Test-Core.ps1 -EvidenceStage stage06
.\scripts\Test-GameAdapter.ps1
.\scripts\Test-Control.ps1
```

Эти скрипты запускают игру и ожидают конкретный диагностический состав. Test-Core требует все три технических плагина и не предназначен для пользовательской поставки с одним sample.server. Не запускай их при активной пользовательской сессии. Steam должен быть доступен для обычных игровых функций. Test-GameBaseline — отдельное исследовательское сравнение, его не нужно выполнять при каждом изменении документации.

Отдельно `.\scripts\Test-ControlCompatibility.ps1` проверяет консоль **на уже запущенной игре**: сам игру не запускает и отправляет только p90.plugins. Выполняй его после обычного запуска нужной копии.

Параметры загрузчика для диагностики: `--p90-core-selftest`, `--p90-adapter-selftest`, `--p90-core-exit-seconds=N` (5…300, отсчёт после создания загрузчика). В обычном пользовательском запуске их нет. Не запускай selftest в публичном лобби.

## Подготовка пакета

Файл `scripts/Package-Nexus.ps1` в рабочем проекте обновляет Documentation, SDK и Development в существующей папке P90 Nexus, проверяет неизменность GameFiles по payload-sha256.json, составляет release-manifest.json и создаёт новый ZIP в artifacts/stage07. Запускай его после изменения документации/исходников. Он не берёт DLL из работающей игры и не заменяет полезную нагрузку скрытно.

При изменении runtime-кода сначала собери и проверь его, подготовь новый GameFiles, обнови его манифест только после осознанной проверки содержимого, повтори установку на чистую копию и сформируй новый выпуск. В GameFiles должны остаться только необходимые DLL и один заявленный образец. Текущий Install.ps1 рассчитан на чистую установку; установка поверх существующей отклоняется.

Пакет не включает bin/obj исходников, SDK-кэши, игровые EXE/DLL, interop, логи, сессии управления или research. Development содержит только наши исходники и скрипты; ссылки на внутренние research-отчёты в старых технических скриптах относятся к рабочему дереву. Для их результатов каталоги создаются при запуске, но исторические материалы автоматически не появляются.

Манифест полезной нагрузки проверяет установщик. release-manifest.json покрывает весь передаваемый комплект, кроме самого себя. ZIP сопровождается внешним SHA-256. Контрольная сумма подтверждает целостность относительно манифеста, но не является цифровой подписью автора.

## Регрессия, откат и приёмка

Для изменения ядра проверяй конфликт ID/команд, неверные метаданные/конфиг, частичный Start, исключение Stop/обработчика, досрочный Dispose, повторный Start и недействительный старый контекст. Для адаптера — поддерживаемую/неизвестную сборку, меню, играющего хоста, чистого клиента, смену сессии и NetId. Существенное сетевое изменение снова требует сценариев CLIENT-TEST у людей.

Перед заменой четырёх системных DLL сохрани предыдущий полный набор. Для отката закрой игру и восстанови согласованный набор DLL и совместимый SDK/API, при необходимости конфиги предыдущей схемы. Установка исходного пользовательского пакета проверена на отдельной копии; адресное удаление добавленных путей описано в README. Новая проверка удаления не должна касаться единственной рабочей установки.

Перед передачей проверь документацию, ссылки, контрольные суммы, отсутствие личных данных, наличие лицензий, установку на чистую игру и отсутствие зависимости от исследовательских каталогов. Не заявляй поддержку новых игровых механик или dedicated только потому, что сборка компилируется.
